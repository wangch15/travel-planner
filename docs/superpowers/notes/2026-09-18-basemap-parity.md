日期：2026-09-18　　對象：`/Users/wangch/GitHub/SENTAI2026/src/basemap.json`（Python + curl 產出）
新版：`trips/_example/basemap.json`（`npm run basemap -- _example`，純 Node）

`trips/_example` 的 `region.bbox` 與 SENTAI 相同（`[139.95, 37.85, 141.45, 39.0]`），所以這一次產出同時是範例行程的真實底圖，也是第 2 階段的驗收比對。

## 怎麼跑的

跑了兩次：

1. **比對用**：`trip.config` 的 `basemap.contourLevels` 暫時指定為 SENTAI 手選的七個值
   `[200, 400, 600, 800, 1000, 1300, 1600]`，讓等高線可以逐層比對。
2. **正式用**：`contourLevels` 改回 `null`，由引擎自動選層級。這是留在 repo 裡的版本。

兩次都是 `dem: "auto"`（日本 → 国土地理院）、`detail: "normal"`。
Overpass 一次成功，未觸發限流；高程圖磚 z10 共 5×5，其中 24 張可用、1 張缺（外海，當成 0 公尺）。

## 已知差異與原因

1. **`sea` 點數 +47%（660 → 970）——預期中的改善。**
   SENTAI 的 `assemble.py` 是取最長的一條海岸線，硬接兩個寫死的外海座標
   （`[142.6, 39.6]`、`[142.6, 36.8]`）閉合成多邊形。那只對「海在東邊」的日本東岸成立，
   換一個地區就會畫反。新版改成把海岸線裁進 bbox，再沿周界順時針走回起點，
   任何地區、任何海陸配置都成立，代價是周界上多了一些點。

2. **向量圖層 +30～60%——查詢範圍不同。**
   如上，SENTAI 的查詢框比行程 bbox 小；新版一律用行程 bbox 外擴 5%。
   限定在同一個框內比較時島數完全一致。

3. **`towns` +96%（24 → 47）——挑選規則不同，是刻意的。**
   SENTAI 用一份寫死的 30 個日本市町名單過濾。新版依規格改成
   「`city` 全留、`town` 依 `population` 取前 20、沒有人口標籤的排最後」，
   名稱走 `name:zh-Hant → name:zh → name` 的 fallback 鏈，不綁任何地區。

4. **自動層級與手選層級不同——不可能相同。**
   SENTAI 的七層是手選的非等距值（…1000, 1300, 1600），新版的自動規則只產生等距層級。
   要重現舊版外觀就在 `trip.config` 明確指定 `contourLevels`。

5. **移植過程中修掉的一個真實缺陷。**
   第一次產出時島數是 380。原因是組裝時把**未簡化**的海岸線直接送進閉合演算法——
   OSM 的海岸線被切成 1,763 段、join 後仍有 1,405 個封閉環，每個岩礁都成了一座島。
   SENTAI 的流程是先跑 `simplify.py`（最短長度 0.004 度、rdp 0.00035）再分離島嶼，
   移植時漏了這一段。補上後島數回到 53（限同框內 46），檔案也從 752 KB 降到 354 KB。
   已加上回歸測試「海岸線先簡化再閉合：太小的碎環不會變成島」。
