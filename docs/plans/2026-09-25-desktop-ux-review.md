# Desktop UX 優化：診斷與計畫（暫存文件）

> **這份文件是暫時的。** 三批優化全部完成後刪除。它的用途是讓實作途中不忘記「為什麼要這樣改」。
> 建立：2026-09-25，依據 desktop 0.1.5 的審查（實際啟動 App 截圖 + 讀程式碼）。分支：`desktop-chat-resilience`。

## 為什麼要做

使用者是非技術背景的行程擁有者。審查發現三個核心問題：

1. **聊天一出錯就鎖死**：大多數錯誤被當成「結果不明」而停用送出，Claude 更是只剩「重新開始」。
2. **設定頁按系統元件分類，不按任務分類**：沒有「準備好了沒」總覽，跨頁依賴只有文字沒有按鈕。
3. **殘留的原型文案與實際行為相反**：到處寫「唯讀」「確認才保存」「原專案未修改」，但 AI 現在會直接改檔並可推送。

保留不動的優點：引導依實際偵測判斷完成度；停止／不明／額度等待分得清楚且不自動重送；
「備份與發布」一句話講清兩者差別、發布前提醒網址公開。

## 第一批：聊天不再卡住

### 1-1 錯誤被歸為「結果不明」→ 送出被鎖

- `desktop/prototype/main.cjs` 失敗處理只有 `LOGIN_REQUIRED / QUOTA_* / POLICY_MISMATCH / MODEL_UNAVAILABLE / INVALID_DAY / EFFORT_UNAVAILABLE`
  算「確定失敗」，其餘（中斷、超時、`AI_TURN_FAILED`、`AI_OUTPUT_INVALID`）都算 uncertain → 送出停用。
- Claude 的 `recover()` 永遠回 `unknown`（`providers/editor.cjs`），所以 Claude 只能「重新開始」。
- 預設錯誤文案說「可以再試一次」，但送出已經鎖了，互相矛盾。
- **改法**：Claude 是一次性子程序（`--no-session-persistence`），程序結束就代表這輪確定結束，應歸為確定失敗；
  只有「可能已在遠端產生效果、且能追回」的 provider（Codex app-server）才維持 uncertain。

### 1-2 Claude 的錯誤原因被丟掉，文案寫死 Codex

- `providers/editor.cjs` 遇到 `result.is_error` 只丟 `AI_TURN_FAILED`，stderr／result 文字全丟。
- `main.cjs` 的 `AI_TURN_FAILED` 文案是「Codex 未完成這次回覆」；`LOGIN_REQUIRED` 等也寫死 ChatGPT。
- **改法**：讀 result／stderr，分類成登入過期、額度用完、服務忙線；錯誤文案依實際 provider 顯示名稱。

### 1-3 慢但正常的回覆被判超時

- `providers/process.cjs` 是從開始計時的**絕對**逾時（一般 180 秒），不看有沒有輸出。
- **改法**：改成「閒置逾時」，每收到輸出就重新計時，另設一個較長的總上限。

### 1-4 送出鍵取決於預覽面板有沒有開

- 預覽只在面板開著時載入；`app.js` 的 `ready` 需要 `realPreview.status` 是 ready。
  面板關著或 AI 剛改完檔，送出就變灰，提示只在 placeholder（一打字就看不到）。
- **改法**：預覽在背景載入，不綁面板開關；預覽失敗時仍可討論（請 AI 幫忙修）。

### 1-5 失敗後的重來

- 失敗後使用者打的字不會回到輸入框。
- **改法**：錯誤下方提供「帶回輸入框」／「重送這則」。

### 1-6 停止回覆可能再轉好幾分鐘

- Codex 的停止只送 interrupt；20 秒沒回應只跳提示，畫面繼續忙碌直到閒置逾時。
- **改法**：停止後在期限內沒結束就強制結束程序並解鎖畫面。

### 1-7 輸入框歷史（使用者追加需求）

仿 Claude Code CLI：在輸入框按 ↑／↓ 瀏覽**這個對話**曾送出的訊息。

- 只在游標位於第一行（↑）或最後一行（↓）時觸發，避免干擾多行編輯；輸入法組字中（`isComposing`）不觸發。
- **未送出的草稿不能丟**：開始往上翻時先暫存目前輸入框的內容；一路 ↓ 回到底時還原那份草稿。
- 翻到某筆歷史後若修改了文字，再往上／下翻也不能無聲丟掉修改（比照 CLI：修改過的那筆保留到送出或離開前）。
- 送出後重置瀏覽位置。

## 第二批：文案與用語一次清乾淨

使用者看得到、且與實際行為相反的文字：

| 位置 | 現在 | 問題 |
|---|---|---|
| `app.js` 開場訊息 | 「AI 提案仍需你確認才保存」 | 輸入框下方同時寫「直接改好存到本機」 |
| `app.js` 預覽頁尾 | 「本機行程預覽 · 原專案未修改」 | AI 會直接改檔 |
| `app.js` 狀態 | 「既有旅程 · 唯讀預覽」「不修改原始檔案」 | 同上 |
| `app.js` 通知 | 「已完成唯讀檢查，原始專案沒有被修改」 | 同上 |
| `onboarding.js` | 「App 只做唯讀檢查，不會改動它」 | 同上 |
| `index.html` 關於頁 | 「既有專案：唯讀驗證與本機預覽」 | 同上 |
| `index.html` iframe title | 「假行程預覽」 | 報讀器會念 |
| `app.js` | 「既有旅程的 AI 修改功能尚未接上」會閃過 | 功能早已接上 |
| 意外錯誤 | 直接顯示 `publisher.status is not a function`、`(128)` | 使用者看不懂 |
| 側欄預設 | 「管理 ChatGPT 連線」 | 用 Claude 的人也看到 |

用語替換方向：提交／推送 →「存一個版本／上傳到 GitHub」；思考強度 →「回覆前想多久」；
Codex →「ChatGPT（Codex）」；模型與思考強度收進「進階」。

## 第三批：設定頁重組（需先給使用者看草圖）

- 最上方新增「開始使用」：GitHub → 旅程資料夾 → AI → Cloudflare（可略過），每項狀態＋一個按鈕；聊天歡迎畫面同步顯示。
- 分類改為：開始使用／帳號連線（GitHub、AI、Cloudflare 同一頁）／我的旅程資料／備份與分享／AI 可以查的資料／外觀／App 更新／關於。
- 所有「先去某某頁做」的文字改成就地按鈕（共 8 處）。
- 引導每步加「稍後再設定」；AI 登入等待加「取消，改用另一個」；Git 安裝加「再開一次安裝視窗」。
