# tp-plan

## 什麼時候用

環境已經準備好（見 `tp-setup`），使用者要開始規劃一趟行程。

## 核心原則

**先盤點、再問、最後才做。** 不要收到一句「我想去北海道五天」就開始查景點——
先把缺的資訊一次問齊，否則你會查一堆最後用不上的東西。

## 步驟

### 1. 收初版

使用者可能給你一段文字、一個檔案、幾張截圖，或是用講的。
把它原樣整理成 `trips/<slug>/docs/brief.md` 的草稿，**先不要加你自己的想法**。

（`<slug>` 用小寫英數與連字號，例如 `kyoto-2027`。）

### 2. 完整性盤點

對照下面的清單，看初版缺了什麼。**這份清單是提示，不是要照抄的問卷**——
問題由你自己列，只問缺的。

- 日期、天數、怎麼抵達與離開
- 目的地區域（決定地圖 bbox）
- 每晚住哪裡：已經訂好的？還是要找？
- 交通方式：自駕（要租車嗎、幾人座、國際駕照）還是大眾運輸（要買 pass 嗎）
- 同行人數與體力（有長輩或小孩嗎、一天能走多久）
- 飲食限制與過敏
- 一定要去的、絕對不去的
- 預算感（住宿等級、一餐大概多少）
- 行程鬆緊：想塞滿還是想慢慢走

### 3. 一次問完

把缺的整理成一組問題，**一次問完**，不要一題一題來回消耗使用者耐心。

拿到回答後補齊 `brief.md`，每個區塊標明是：

- **使用者已定，只查核** —— 例如已經訂好的飯店，你只需要確認地址與入住時間
- **請 agent 建議** —— 例如「第三天不知道要去哪」

要找住宿的話，列候選並附官網連結。**你不代訂任何東西**——不訂房、不訂位、
不買票。給連結，讓使用者自己決定、自己付錢。

### 4. 建立行程資料夾

```
npm run new -- <slug>
```

然後填 `trips/<slug>/trip.config.json`。幾個要注意的：

- `region.bbox` 是 `[lngMin, latMin, lngMax, latMax]`。把所有目的地包進去，
  四周再留一點邊。太小的話底圖會缺角、座標驗證會擋掉合法的地點。
- `party` 只用來算「N 人約 …」的餐費，`currency` 是金額前綴。
- `sections` 用不到的區塊就關掉，關掉的不渲染也不驗證。
- 欄位細節見 `docs/schema/trip-config.md`。

### 5. 寫逐日草案

寫 `trips/<slug>/docs/plan.md`：

- 每天一段：主軸是什麼、大概去哪幾個點、怎麼移動、住哪
- 每天列出**備案**（下雨、走累、店休）與**待確認事項**
- 標出你不確定的地方，讓使用者知道哪些還要討論

這份是給人看的文字草案，**還不要碰五個資料檔**。

### 6. 閘門一：請人確認

**把 `plan.md` 給使用者看，等他確認。**

確認之前：

- 不要碰 `data.js`、`details.js`、`dining.js`、`map-lists.js`、`photos.json`
- 不要做深度查核（查營業時間、查路線、查停車場）

原因很簡單：整天的行程順序如果要改，先查好的那些資料有一半會作廢。
先確認骨架，再花力氣填細節。

## 完成後

`plan.md` 確認了，接著用 `tp-research` 開始查核並填資料檔。
