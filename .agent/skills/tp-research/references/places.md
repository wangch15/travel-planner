# 查地點

目標：填好 `data.js` 的 `PLACES` 與 `details.js`。

## 每個地點要查到的東西

| 要查 | 填進 | 怎麼查 |
|---|---|---|
| 座標 | `lat`／`lng` | Nominatim、Overpass，或 Google Maps 上右鍵複製座標 |
| 當地語言名稱 | `local` | 官網標題、OSM 的 `name` 標籤 |
| 搜尋字串 | `gq` | 當地語言的完整名稱，給 Google Maps 搜尋用 |
| 分類 | `cat` | `hub`／`stay`／`sight`／`food`／`shop` |
| 營業時間與費用 | `details.info` | **官網**，不要用旅遊網站的轉述 |
| 旅行當天是否公休 | 不填欄位，有問題就進 `CHECKLIST` | 官網的公休日說明 + 當地國定假日 |
| 建議停留時間 | `details.stay` | 官網的建議路線、或實際規模判斷 |
| 為什麼值得去 | `details.summary`（至少 40 字） | 你自己寫，但要基於查到的東西 |
| 看點 | `details.highlights`（至少 2 點） | 同上 |
| 出處 | `details.refs`（至少 1 筆官方來源） | 官網網址 |

## 座標的陷阱

- **連鎖店會配錯分店。** 搜尋店名常常會配到市中心的分店而不是你要的那間。
  用地址或座標確認，必要時在 `gurl` 直接放官方的 Google Maps 連結。
- **大型景點的座標要放對地方。** 一座山、一個公園，座標放正門或停車場入口，
  不要放幾何中心——那可能在山裡面。
- **住宿用街區層級就好**，並標 `approximate: true`（見 `.ai/rules/privacy.md`）。
- 座標必須落在 `trip.config` 的 `region.bbox` 內，否則 `check` 會擋。
  真的在範圍外就是 bbox 該放大。

## summary 要寫什麼

至少 40 字，而且要回答「為什麼值得去」。

- ✗ 「立石寺是山形縣的一座寺廟。」——這是廢話，使用者已經知道了
- ✓ 「立石寺建於西元 860 年，從山門到奧之院共一千零十五階石階，沿途穿過杉木林
  與岩壁上的堂宇，登頂後的五大堂可以俯瞰整個山谷。」——有畫面、有規模感、
  看得出要花多少體力

## 公休日

**這是最常出錯的地方。** 很多地方的公休是「每週幾」或「每月第幾個週幾」，
不是固定日期。查的時候要換算到**旅行的那一天是星期幾**。

國定假日也要查：有些地方假日照常營業、有些反而休息、有些人多到進不去。

查不到就寫進 `CHECKLIST`：「出發前確認 X 在 10/13（週二）是否營業」。
